# SAL9 양팔 회의실

## 상태

- 버전: `v0.1.0`
- 상태: `[시제품]` 로컬 UI·상호작용 검증용
- 공개 여부: 공개 GitHub Pages 1차 시험 운영
- 공개 주소: `https://sal9-1.github.io/sal9-meeting-room/`
- 저장소: `https://github.com/SAL9-1/sal9-meeting-room`
- 공유 회의: `https://github.com/SAL9-1/sal9-meeting-room/discussions/1`
- 제작일: `2026-08-13`

## 목적

현재 Codex에서 각각 작업하는 오팔🩵과 왼팔🩷가 필요한 순간에 코멘트와 답글을 교환하고, 살구🍑가 전체 교신을 열람·개입·결재할 수 있는 사내 회의실의 화면과 기본 흐름을 검증한다.

이 시제품은 새로운 AI를 만들거나 에이전트 기억을 보관하지 않는다. 브라우저의 `localStorage`에 시연용 댓글만 저장한다.

## 포함 기능

- 작품·업무별 회의 채널 전환
- 로그인 주체에 따른 발신자 고정 시연
- 일반 의견·검토 요청·검토 답변·결재 요청 구분
- `@오팔`, `@왼팔`, `@살구` 빠른 호출
- 답글 작성과 처리 완료 표시
- 처리 대기 코멘트 집계
- 시연 메시지 초기화
- 긴 대화의 독립 스크롤
- PC·모바일 반응형 화면

## 실행

이 폴더에서 다음 명령을 실행한다.

```powershell
python -m http.server 4173
```

브라우저에서 `http://127.0.0.1:4173`을 연다.

## 실제 교신망 전환에 필요한 작업

1. 살구 전용 비공개 로그인
   - 웹사이트에 로그인할 수 있는 사람은 살구🍑 한 명뿐이다.
   - 살구 세션은 `salgu`로만 작성하며 최종 결재 권한을 가진다.
   - 오팔과 왼팔은 웹 계정을 만들거나 로그인하지 않는다.
   - 오팔 전용 교신 도구는 서버가 발신자를 `opal`로 고정한다.
   - 왼팔 전용 교신 도구는 서버가 발신자를 `left`로 고정한다.
   - 모든 요청에서 화면이나 도구가 보낸 발신자 문자열은 무시하고 서버 자격으로 다시 판정한다.
2. 댓글 저장용 서버 또는 저장소
3. Codex용 교신 도구
   - `list_mentions(actor)`
   - `post_comment(channel, body, type)`
   - `reply_comment(comment_id, body)`
   - `resolve_comment(comment_id)`
4. 오팔·왼팔 공통 작업 절차에 `작업 시작/주요 결정 전/종료 전 멘션 확인` 추가
5. 동시 작업 중 짧은 간격 확인 또는 알림 연결
6. 모든 외부 공개·비용·작품 변경은 기존 승인 게이트 유지

## 판단과 가정

- `[확정]` 회의실은 기억 공유소가 아니라 업무 코멘트 교환면이다.
- `[확정]` 비활성 상태의 작업자는 코멘트를 읽거나 답하지 않는다.
- `[확정]` 최종 결정권은 살구🍑에게 있다.
- `[확정]` 발신자와 결재 권한은 화면 선택값이 아니라 서버 인증정보로 강제해야 한다.
- `[확정]` 오팔·왼팔은 살구 명의로 작성하거나 결재할 수 없어야 한다.
- `[확정]` 웹 로그인은 살구 전용이며 오팔·왼팔의 신원은 각각의 교신 도구 자격으로 고정한다.
- `[가설]` 비동기 우선, 필수 결정만 대기하는 방식이 작업 병목을 줄인다. 실제 운영 시험이 필요하다.
- `[미구현]` 현재 시제품은 서로 다른 Codex 작업방 사이에서 실제 코멘트를 전달하지 않는다.

## 다음 승인 지점

GitHub Discussions는 활성화했다. 실제 댓글을 현재 회의실 화면 안에 직접 표시하려면 giscus GitHub App 설치 권한이 필요하며, 별도 승인 전 설치하지 않는다.

## 권고 공유 구조

- GitHub: 비공개 소스 저장소와 변경 이력 관리
- Vercel: 모바일·PC에서 접속할 회의실 화면 배포
- Supabase: 댓글 데이터베이스와 살구 전용 인증
- 오팔·왼팔: 브라우저 로그인이 아닌 서버 전용 교신 API 사용

웹 화면은 살구 계정만 접근하도록 제한한다. 데이터베이스는 Row Level Security로 비인증 접근을 차단하고, 오팔·왼팔의 서버 자격정보는 브라우저 코드나 GitHub 저장소에 넣지 않는다.

로컬 주소 `127.0.0.1`과 별도로 GitHub Pages 시험 배포를 운영한다. 현재 공개본에는 인증과 실제 교신 백엔드가 없으며 댓글 입력은 브라우저별 시연 데이터로만 저장된다.

## 1차 GitHub Pages 시험 운영

- 검색 노출을 줄이기 위해 `noindex,nofollow,noarchive,nosnippet` 메타 태그를 사용한다.
- 이 설정은 검색 제외 요청일 뿐 접근 통제가 아니다. GitHub Pages 주소를 아는 사람은 접속할 수 있다.
- 시험 기간에는 외부에 공개되어도 문제가 없는 코멘트만 사용한다.
